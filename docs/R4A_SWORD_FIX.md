# R4-A 骷髅死亡备用木剑反馈修复

2026-10-09。用户在骷髅/僵尸实机验收中反馈骷髅死亡高概率掉满耐久木剑，要求修正后进入下一阶段。唯一目标 `26.3/`、分支 `26.3`，开始 HEAD `f0e5a0811e1f99f204db7049ef5350d59a46c34b`，工作树干净。旧 `26.3-tests` 严格只读。

## 根因和实现

新骷髅模块每次合格新生拥有真实备用木剑，默认 `reserve_drop=0.085`。死亡前归还原弓，随后 AFTER_DEATH 用 `spawnAtLocation` 直接掉备用武器。这个自定义链路没有原版装备掉落的玩家击杀条件和随机耐久处理，因此生成剑作为完整物品进入掉落。反馈中的“高概率”未做大样本概率测量，不伪称已经量化。

- `SkeletonState.java`：只给模块新生成木剑添加私有 CustomData 来源标记，随真实物品交换、保存和转化，不复制装备。新外部普通木剑即便无名字和无损耗，也不根据外观认定为生成物。
- `SkeletonBehavior.java`：死亡前先归还原弓，再移除持手或备用槽中的自有生成剑；AFTER_DEATH 再防守过滤生成物。禁用仍做物品结算，不将临时装备变成战利品；真实外部装备保持既有掉落和组件。
- 已知旧版 v1 的首次加载，在没有新策略标记且弓/默认木剑成对时进行一次来源补标；不改变附件版本，不补发剑，不接管未知版本数据。
- `SkeletonBehaviorTests.java`：新增 4 项实际 Goal/死亡/保存回归；既有双武器死亡守恒测试现在明确布置外部命名耐久木剑，并保留“一弓一剑”的原断言及组件断言。这是用户要求改变生成物掉落后的测试范围澄清，不删除守恒验收。

**旧数据限制**：旧版没有来源信息，与默认生成剑完全相同的外部木剑无法可靠区分。仅旧 v1 中、数量 1、与弓配对、组件完全为原版默认的木剑会被补标；旧命名/损伤/组件定制剑及新外部默认木剑保留。此限制是现存数据歧义，不宣称可无损追溯所有旧外部物品。

环境固定：MC26.3 / Java25.0.3 / Gradle9.7.1 / Loom1.18.3 / Loader0.19.5 / API0.162.0+26.3 / 官方未混淆命名；Fzzy0.7.7+fix3+26.3、Kotlin1.14.1+kotlin.2.4.20。未升级依赖、改 Mixin 注入或引入新装备。

## 人工复测

1. 固定依赖/default 配置，普通或困难难度，遮阳场地；使用刷怪蛋生成普通骷髅、流浪者、沼骸，将无 AI 铁傀儡放在约 2 格，合理等待 2～5 秒，确认实际切到木剑并造成近战伤害。
