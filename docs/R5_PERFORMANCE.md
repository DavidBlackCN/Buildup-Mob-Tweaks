# R5 性能对照（限定 PASS）

2026-10-11，在同一机器顺序运行空白依赖组合→正式包全局关闭→正式包默认开启，没有同时运行其他测试服务器或客户端。固定 seed55113、normal、视距/模拟距离3、20 tick/s、512MiB～2GiB堆；Java25.0.3、Windows11 build26200、Intel64 Family6 Model198 Stepping2、20逻辑处理器。系统硬件/WMI查询受限，未获取可信物理内存或完整CPU型号，不虚构信息。

测量为原版 `MinecraftServer.tickServer(BooleanSupplier)` HEAD→RETURN 的时间，包含独立探针END事件少量观察开销，不包含维持20TPS的睡眠。每场先预热120刻，再连续采样240刻，四场景各重复两次，三组共24场/5760测量刻。采样前确定预算为 **p95 <50ms**（20TPS的单tick容量），不采用事后挑选的比例门槛。所有场景PASS，默认开启最高p95 **4.6161ms**；这不是在任意机器或生产世界的承诺。

## 固定输入及实际工作量

所有组均 **0玩家**，不能解释为多人容量压测。三组统一关闭自然刷怪、随机方块Tick与mobGriefing，固定夜间；“默认开启”指正式Mod默认配置，世界输入仍是上述受控条件。强制加载5×5场地区块，原生chunk cache最终记录961个加载区块（并非只加载25个）。每场先快照清理全部非玩家实体并重建场地，空闲场实体数必须为0。

- idle：0个生物。
- mixed：96个固定类型/位置蓝图，骷髅、僵尸、掠夺者、女巫、唤魔者、烈焰人、苦力怕、蜘蛛轮换，原生AI正常运行。
- combat：相同96个生物及32个NoAI铁傀儡作为真实受击目标，输入初始目标后由正常Goal/Brain推进。原生最大生命属性有上限，损失量以实际初始生命记录，非所请求的超大值。
- village：96个村民/牛/鸡/猫，加工作方块等有限POI输入，保留原生Brain。不是完整自然村庄、袭击或刷怪塔。

保持正式随机出生路径，固定后续生物随机源不是固定已经发生的出生抽取，所以战斗后存活、弹体、附属实体数不会完全一样。没有为追求相同最终实体数关闭正式功能；最终数量、目标、Goal与实际受伤均保留。以下每格为 **mean / p95 / max，单位ms**。

## 复现与未运行项

根目录执行 `python docs/rebuild/scripts/r5_bench.py <新编号>`，需要已解析本地依赖及最新正式JAR；隔离目录须不存在，避免覆盖旧证据。完整命令、exit0和设置在外层 `bench-*-3-command.json`；汇总[performance-3.json](../../docs/rebuild/evidence/r5/performance-3.json)保存24场全部逐tick纳秒数据与分位数；单场原始JSON和日志同目录保留。探针源码 `R5Bench.java` / `R5TickMixin.java` 独立编译，不进入正式包。

第一次无效尝试测量241刻，第二次实体清理遍历失效且生命损失基准错误，两者已修正后完整重跑，不能混入本表。最终输入校验：24场每场240刻、所有idle实体0、同一蓝图与加载范围；没有选择旧低值替换新值。

实际多人压力、大视距/大世界、连续袭击、刷怪塔、长期自然出生、第三方Mod和CPU调用栈热点分析均 **NOT RUN**。双客户端协议验证是另一项功能测试，不与这里的0玩家采样混用。[最终报告](PHASE1_FINAL_REPORT.md) / [兼容矩阵](COMPATIBILITY_MATRIX.md)。
